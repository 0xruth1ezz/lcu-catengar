**建议把主界面收敛为「两个自动化开关 + 英雄库 + 优先列表」。正常连接只占一句简短状态，诊断信息按需展开。** 当前最明显的机会是重新分配空间和注意力。

头像、选中勾和优先级编号已经体现了这款工具的用途；统一的深色主题也有基础。值得保留的是两个独立开关、左侧添加右侧排序的直接路径，以及不抢焦点的成功提示。当前通用卡片和外围状态占据过多空间，让主功能缺少足够的视觉分量。

**1. [P1] 把日常使用不需要的信息移出主视图。**

截图里，连接情况在顶部和底部日志重复出现，历史日志还保留「正在连接」。用户需要自己判断哪一句代表现在。外观下拉框、重新连接、三行日志和资源统计，共同挤压了英雄区。

| 现有内容 | 建议处理 |
|---|---|
| 已连接 · WebSocket 实时监听 | 顶栏简写为「客户端已连接」；协议进入连接详情 |
| 重新连接 | 放进连接详情；恢复失败且需要人工处理时就地显示 |
| 外观下拉框 | 移入「设置 → 外观」 |
| LCU 认证、WebSocket、REST、过程日志 | 移入默认收起的「诊断」 |
| 英雄、头像、符文、符文系资源统计 | 放进诊断；搜索结果数量可留在英雄库局部 |
| 已接受 0 · 已选取 0 | 放进本次运行详情，避免零值常驻 |

这里需要保留一个重要出口：**需要用户处理的问题仍在主界面出现。** 授权失败、无法连接、设置保存失败，应说明影响并给出对应动作。源码中设置保存失败目前只写日志，因此实施时要先将这类错误单独呈现，再折叠日志。相关位置：`src/app.native:89`、`src/app.native:93`、`src/service.zig:95`。

对应命令：`$impeccable distill`。

**2. [P1] 让开关回答「会做什么、何时生效」。**

两个开关应继续保持独立、首屏可见，卡片高度可以收紧。开关下方用一句与实际条件一致的状态，替换始终相同的说明：

- 关闭时：「已关闭」。
- 开启但未连接：「已开启 · 等待客户端」。
- 自动接受开启且等待匹配：「已开启 · 等待匹配成功」。
- 自动选取开启但名单为空：「先添加优先英雄」。
- 自动选取已配置且等待选人：「已开启 · 等待进入选人」。
- 进入不支持的模式：「当前模式不支持自动选取」。

这些是不同状态下的替代文案，不是同时增加六条提示。断线时保留用户已开启的偏好，同时说明暂时无法执行；连接成功本身也不能暗示两个功能已经开启。功能适用范围保留为简短辅助说明。

对应命令：`$impeccable clarify`。

**3. [P2] 把释放的空间交还英雄配置，明确顺序的意义。**

建议保留「左英雄库、右优先列表」，移除中间的大箭头，将双栏从等宽调整为约 **60:40**，作为默认窗口下的起点。英雄库更需要浏览面积；右侧要为英雄名和排序按钮保留足够宽度，并在最小窗口下验证。

「我的优先顺序」下补一句「越靠前越优先，只换更高优先级的可用英雄」。空列表给出「从左侧添加想玩的英雄」。把金色重点留给已选英雄、优先级与开启状态；「极地助手」「2 / 32」「客户端空闲」可使用普通文字或中性样式。

右下的「尚未分配英雄 / 可用池 0 位」只在选人场景有意义。空闲时收起这块大卡片，进入选人后再显示当前英雄及与选择有关的信息。底部不再为日志和统计固定预留大块高度。
